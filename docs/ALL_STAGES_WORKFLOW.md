# MEDPAR QA Automation — Five-Stage Workflow

## Stage order

1. Final Action
2. Four-Year Split
3. Stay
4. Intermediate
5. Final MEDPAR

Each stage accepts JSON or Parquet records using three roles:

- `source`: records consumed by the stage
- `actual_output`: output generated by the system under test
- `expected_output`: approved golden output

The framework never combines files from different stages into the same group.

## Common execution

1. Discover all matching files.
2. Read and attach file/row lineage.
3. Resolve field aliases into canonical names.
4. Validate required identities and types.
5. Group records with the stage-specific key.
6. Calculate known expected business values.
7. Validate actual output structure.
8. Compare expected output and actual output when both are supplied.
9. Reconcile missing, duplicate and unexpected records.
10. Produce structured PASS, FAIL, NOT_APPLICABLE or BLOCKED evidence.

## PASS/FAIL policy

A stage passes only when it contains no FAIL or BLOCKED result. Missing optional actual/golden files produce NOT_APPLICABLE, while files configured as required produce FAIL when absent. Unknown business rules are never silently reported as PASS.

## Current unresolved specifications

- Final Action Rule 6 ICN/Action Code decision matrix
- Exact source derivation for selected Stay fields where no mapping was supplied
- Complete Intermediate source-to-target mapping for every field outside the selected regression scope
- Final MEDPAR 3050-to-3000 field offsets and transformation mapping

The framework can compare approved expected outputs for these fields immediately. Source-derived calculation should only be enabled after the mapping is approved.
